<Synopsis cmd="mead env" />

`env` reports **what is installed on this machine**, based on `.mead/state.json`. Use it to answer "where does `import \"example_pkg\"` actually point?"

## Output

```txt
project  /home/you/orchard
cache    /home/you/.cache/mead
odin     /home/you/odin/odin

Dependency bindings:
  example_pkg      /home/you/orchard/deps/example_pkg/src/geometry  (6e93eafa715d)
  renderer         not installed

Tools:
  assetgen         /home/you/orchard/deps/.tools/assetgen/bin/assetgen  (7e1e798f44a1)
```

| Field | Source |
| --- | --- |
| `project` | The directory that holds `meade.kdl`. |
| `cache` | `$MEAD_CACHE_DIR`, or the [platform default](/reference/environment#mead_cache_dir). |
| `odin` | `$MEAD_ODIN` or `odin`, looked up on `PATH`. Shows `not found` when missing. `env` doesn't run the compiler. |
| Dependency bindings | Each declared dependency's package directory and installed commit, or `not installed`. |
| Tools | Each declared tool's executable and installed commit, or `not installed`. |

When a section is empty, it prints `none`.

## Errors

`env takes no arguments`, plus any manifest validation error.
