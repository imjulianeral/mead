```kdl
targets {
    target "app" kind="executable" path="src" {
        flags "-o:speed" "-define:LOG_LEVEL=2"
    }
    target "core" kind="static-library" path="src/core"
}
```

`targets` takes no arguments or properties. Its only allowed child is `target`.

Targets serve two purposes. **Your project builds them** with [`mead build`](/cli/build) and [`mead run`](/cli/run). And **consumers build them**: when another project declares your repository as a [tool](/manifest/tools), mead builds the named executable target.

## Flags mead controls

mead sets the output path, build mode, and target platform itself, so a manifest can't override them:

| Rejected | Why |
| --- | --- |
| `-out:…` | mead writes to `.mead/bin/`, or to the tool artifact cache. |
| `-build-mode:…` | It comes from `kind`. |
| `-collection:…` | Dependencies resolve through bare names, not collections. |
| `-target:…`, `-subtarget:…`, `-target-features:…`, `-microarch:…` | mead owns the target platform. Tool artifact keys record the host OS and architecture. |
| `-file`, `-no-entry-point` | mead always builds a package directory. |

```txt
mead: error: meade.kdl:14:15: flag "-out:bin/app": mead controls this compiler argument
```

Everything else, such as `-o:speed`, `-debug`, `-define:…`, `-vet`, or `-extra-linker-flags:…`, passes through.

:::note
Library kinds work for **your own** targets today. Compiled-library contracts and bindings for *consumers* are milestone 6.
:::
