mead installs Odin dependencies **directly from their authors' Git repositories**. You don't need a mead registry, a repackaging service, or a registry account. You name a dependency, point it at a Git origin, and choose a revision. mead resolves that revision to an exact commit, records it in `mead.lock`, and installs the source under `deps/`.

```odin src/main.odin
import example "example_pkg"
```

The dependency name `example_pkg` comes from your manifest. When you run `mead build`, mead resolves it to the installed package. The stock Odin compiler does the rest.

## What mead 0.1.0 does

mead 0.1.0 implements **design milestones 1–3 on Linux**. It can:

- read and validate `meade.kdl` manifests (`schema 1`, KDL v2)
- list the releases, tags, and branches of a Git origin
- lock exact commits and install sources under `deps/`
- build projects that use bare dependency imports, with the stock compiler
- build project tools from source and run them with `mead exec`

:::warning[Not yet implemented]
Recursive dependency graphs, release-asset tools, version ranges, compiled libraries, and editor integration are not implemented yet. See [Implementation status](/reference/status).
:::
